# Проверка зависимостей и образов

Python-зависимости закреплены в `backend/uv.lock`, npm — в `frontend/package-lock.json`. `urllib3` обновлён до 2.8.0. MinIO и storage-init используют обновлённые Go-модули из `infra/minio/go.mod`/`go.sum`; исходный commit и SHA-256 архива закреплены в Dockerfile. Изменения зависимостей доступны в проекте вместе с командами сборки. PostgreSQL 17 использует Debian 13 и пересобранный Go 1.27 `gosu` с отдельными lock-файлами. AGPL/LICENSE/NOTICE MinIO и лицензия gosu сохранены в образах.

Приложения запускаются без root, с read-only filesystem, без writable-томов и сброшенными capabilities. Сетевые порты PostgreSQL и MinIO не опубликованы. Эти ограничения уменьшают поверхность атаки, но не являются исправлением любой уязвимости в зависимости.

## Повторная проверка

После сборки установите Trivy из [официального репозитория](https://github.com/aquasecurity/trivy), затем выполните с тем же env-файлом, что используется для Compose:

```sh
scripts/check-security.sh
npm --prefix frontend audit
uv export --directory backend --frozen --no-dev --no-hashes --format requirements-txt -o /tmp/catalog-requirements.txt
uvx pip-audit -r /tmp/catalog-requirements.txt --no-deps --disable-pip
```

`check-security.sh` проверяет уникальные runtime-образы Compose и завершится ошибкой при HIGH/CRITICAL с доступным исправлением. Отсутствие установленного сканера тоже даёт ошибку. Флаг `--ignore-unfixed` относится только к этому автоматическому порогу: он не объявляет остальные записи безопасными. Для полного отчёта запускайте `trivy image --scanners vuln IMAGE` без этого флага; учитывайте дату базы и фактическую достижимость уязвимого кода. Не используйте `audit fix --force` и не удаляйте metadata пакетов, чтобы скрыть результаты.

## Остаточные ограничения

- В актуальных закреплённых базах Debian остаются предупреждения по системным пакетам без опубликованной исправленной версии для стабильного выпуска. Обновление баз и удаление ненужных pip/npm не устраняет эти записи. Требуется повторный разбор перед публичным размещением и после появления обновлений; следующая плановая проверка — не позднее 23.11.2026.
- В PostgreSQL-образе Trivy классифицирует CVE-2026-6653 в libxml2 как Critical. [Debian Security Tracker](https://security-tracker.debian.org/tracker/CVE-2026-6653) подтверждает отсутствие исправления в Trixie и относит проблему к minor/no-dsa. Приложение не использует XML-типы/функции PostgreSQL, не принимает SQL от клиента и не публикует порт БД. Путь эксплуатации через HTTP API проекта не установлен. Это ограничение применимости, а не заявление об исправлении libxml2; произвольный SQL-доступ изменяет оценку риска.
- Для `golang.org/x/crypto` сканер сообщает GO-2026-5932: пакет OpenPGP не сопровождается и не имеет исправленной версии. В проверенной сборке MinIO `go tool nm` не обнаружил символов OpenPGP; в отчёте `govulncheck` осталась только запись на уровне модуля. Само наличие модуля не доказывает использование OpenPGP. Не следует включать этот пакет в новые функции. Дополнительно обнаруженный Go-анализатором GO-2026-6107 устранён обновлением `etcd/client/pkg/v3` до 3.5.33.
- Репозиторий MinIO Community архивирован. Обновлённая локальная сборка проходит проверки S3 этого проекта, но не получает автоматически гарантий сопровождения всего upstream. Для длительного production-размещения нужен поддерживаемый процесс обновления MinIO и его зависимостей.

Каталог и изображения публичны по назначению. Корзины, заказы и Telegram-идентичность защищены серверной сессией. Перед передачей замените токен бота, если он сообщался в переписке; секретные env-файлы не должны входить в репозиторий или архив.
